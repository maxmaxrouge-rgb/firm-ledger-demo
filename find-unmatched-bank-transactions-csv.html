How to find unmatched bank transactions in CSV files

[inferred: query choice] This guide targets “how to find unmatched bank transactions in CSV files”. A firm reviewing an exception list could type this query. Search volume and purchase intent have not been measured.

1. Establish a matching baseline

[verified: fetched live template and local engine run]

Download the sample CSV. Save identical copies as ledger.csv and bank.csv. The synthetic sample has these rows:

client,reference,date,description,gross_cents,gst_cents,kind
my-business,receipt-1,2026-01-15,Customer receipt,11000,1000,sale
my-business,purchase-1,2026-01-16,Materials,-5500,500,purchase

Open the live sample. Choose both files under “Import your own CSVs”. Select “Load and reconcile locally”. The local engine returns 2 matched ledger rows and 0 exceptions for these identical files.

2. Make one reference differ

[verified: local engine run with the fetched sample]

In bank.csv only, replace receipt-1 with bank-receipt-1. Keep the date and amount unchanged. Load both files again.

The local engine returns 1 matched ledger row and 2 exceptions. One exception is the ledger receipt. The other is the bank receipt. They represent a single transaction pair with different references.

The demo matches reference, date and gross amount within each client. Description and GST do not establish a match. Equal amounts alone do not establish a match.

3. Investigate the two exception rows

[inferred: suggested review procedure]

Compare each exception with the original statement and ledger. Check the client, reference, date and signed amount. Record whether the references describe the same source transaction.

An unmatched row does not prove that cash is missing. A reference difference can prevent an exact match. Keep the original exports unchanged while you investigate.

Record the reason for each exception. The firm decides whether a source record needs correction. Do not change a reference only to remove an exception.

4. Check the file and model limits

[verified: fetched demo source and offer]

Use the template headers and integer cents. Keep each client/reference pair unique within a file. Supply one calendar year per file pair. The demo accepts up to 10,000 rows and 2 MB per file.

The exact-match demo does not resolve split transactions or fuzzy references. The simplified model does not support refunds or adjustments. Imported CSVs are processed in the browser tab. Refreshing clears imported data.

This sample uses synthetic data. It does not establish suitability for your client files. The BAS-style figures are illustrations, not tax advice or lodgement.

For file preparation and a date-difference example, read how to reconcile bank and ledger CSV files.
