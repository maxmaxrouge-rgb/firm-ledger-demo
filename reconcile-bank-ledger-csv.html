How to reconcile bank and ledger CSV files

For accounting and bookkeeping firms assessing a CSV reconciliation workflow.

[inferred] This guide targets the query “how to reconcile bank and ledger CSV files”. The query reflects the proposed pilot task. Search volume and buyer intent have not been measured.

1. Prepare two files from the template

[verified: fetched live demo and template.csv; local parser run]

Download template.csv. Save two copies as ledger.csv and bank.csv. Keep the header and both example rows:

client,reference,date,description,gross_cents,gst_cents,kind
my-business,receipt-1,2026-01-15,Customer receipt,11000,1000,sale
my-business,purchase-1,2026-01-16,Materials,-5500,500,purchase

The example receipt is AUD 110.00. The purchase is AUD -55.00. Amounts use integer cents. GST amounts are positive.

Both files need the same columns in the same order. Keep client IDs consistent. Each client/reference pair must be unique within each file.

Use dates in YYYY-MM-DD format. Supply one calendar year per file pair. Each file supports up to 10,000 rows and 2 MB.

Use kind sale, purchase, or excluded. Sales use positive amounts. Purchases use negative amounts. Excluded rows need zero GST.

2. Load the matching example

[verified: fetched demo source; local matching-engine run]

Open the live demo. In “Import your own CSVs”, choose ledger.csv and bank.csv. Select “Load and reconcile locally”.

The two unchanged template copies produce 2 matched ledger rows and no exceptions in the local engine check.

The demo matches reference, date and gross amount for each client. It does not use description or GST to establish a match.

3. Create one date mismatch

[verified: local matching-engine run using the fetched template]

In bank.csv only, change the purchase date from 2026-01-16 to 2026-01-17. Keep the ledger file unchanged.

Load both files again. The local engine check produces 1 matched ledger row and 2 exceptions.

The exceptions are the ledger purchase and the bank purchase. Their dates differ, so neither has an exact counterpart.

These 2 exceptions represent one changed transaction pair. They do not prove that money is missing.

4. Review the source records

[inferred: suggested review procedure]

Compare each exception with the source ledger and statement. Check the client ID, reference, date and signed amount.

A posting date difference can prevent an exact match. A changed reference can also prevent a match.

Record the reason for each difference. The firm decides whether any accounting change is needed.

Do not change a source record only to make the demo match. The demo does not handle fuzzy matches or split transactions.
